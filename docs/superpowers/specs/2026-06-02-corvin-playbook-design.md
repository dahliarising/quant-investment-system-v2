# Corvin Playbook — 종목별 플레이북 + 시각 대시보드 설계

- **작성일**: 2026-06-02
- **상태**: Design (승인 대기)
- **출처**: Discord 브레인스토밍 (폐하 ↔ Corvin), 2026-06-01~02

## 1. 배경 / 문제

자동 리딩 브리핑(`run_leading`)이 "시장 신호"만 나열해 부실하다는 피드백. 폐하가 원하는 것은
**각 모니터링 종목의 "타이밍 + 비율"이 머리에 쏙쏙 들어오는 방안**.

진단 결과 우선순위 (폐하 선택 **B > C > D**, A 제외):

- **B (최우선)** — 종목별 진입/익절 기준(존·비율)이 **일관**돼 기억에 박혀야 함 ("플레이북")
- **C** — 숫자가 흩어지지 않고 **한눈에** (시각화)
- **D** — **언제** 움직일지 트리거 신호
- (A 필터링은 핵심 문제 아님 — 모든 종목이 플레이북을 가져야 함)

## 2. 목표 / 성공 기준

- 모든 모니터링 종목(현 50) + 보유 종목이 **동일 구조의** 매수/익절 래더를 가진다.
- 래더 = **고정 규칙**으로 자동 계산 (종목마다 가격 레벨만 다름 → 구조는 동일 → 기억).
- 두 화면: ① 매일 텍스트 푸시(액션 중심) ② 상시 HTML 대시보드(전 종목 시각 플레이북).
- 종목별 **stance**는 `portfolio.json` + 평단 대비 가격으로 자동 결정 (§4.0) → 정합성 가드레일 자동 준수.

## 3. 접근 (선택: 접근 1 — 고정룰 래더)

- **접근 1 (채택)**: 종목마다 동일 규칙으로 존 자동계산. 일관성 = 기억(B 최우선). MVP.
- 접근 2 (기각): 4-pillar 신호 연동 동적 존 — 존이 매번 움직여 기억 어려움(B와 충돌).
- 접근 3 (향후 확장): 고정룰 + 4-pillar 신호를 "확신도 뱃지(🔥/⚪)"로 오버레이. MVP 안정화 후.

## 4. 플레이북 규칙 (핵심)

**구조는 전 종목 동일. 가격 레벨만 종목별 기술지표에서 산출.**

### 4.0 Stance 결정 (어느 래더를 보일지)
`portfolio.json` 보유 여부 + 평단 대비 가격으로 자동:
- **ENTER** (미보유) → 매수 래더
- **ACCUMULATE** (보유 + 평단 근처/하단, 즉 PnL ≤ +5% 또는 DCA 진행 노트) → 추가매수 래더
- **HARVEST** (보유 + 수익 확장, PnL > +5%) → 익절 래더

예: 한화에어로(보유·−7.3%)=ACCUMULATE(매수존), MSFT(보유·+20%)=HARVEST(익절존), BWXT(미보유)=ENTER.
※ ACCUMULATE도 코어 손절 라인(MA50 이탈)은 표시 — 매수와 리스크 동시 인지.

### 매수 래더 (ENTER·ACCUMULATE) — 비율 30 / 40 / 30
- **Z1 30%** 1차 눌림 — MA20
- **Z2 40%** 핵심 지지 — MA50 (무게중심)
- **Z3 30%** 딥밸류 — MA50 −5% 또는 RSI<30 수준
- 가격이 이미 MA50 하단이면: Z1=현재 probe, Z3=MA50 회복 확인(추세 전환 매수)으로 매핑.

### 익절 래더 (HARVEST) — 비율 33 / 33 / 34
- **Z1 33%** 과열 — RSI≥70 또는 가격 ≥ MA20×1.10
- **Z2 33%** 전고 / 52주 고가 밴드
- **Z3 34%** 코어 홀드 — MA50 종가 이탈 시 청산

### 상태 뱃지
- 🟢 지금 매수 (현재가가 활성 매수존 밴드 내)
- ✂️ 지금 익절 (익절존 밴드 내)
- ⏳ 존 대기 (존 사이)
- ⚠️ 무효화 (핵심 레벨 종가 이탈 — 매수는 신저가, 익절은 MA50 이탈)

### 워크드 예시 (실데이터 2026-06-01)
- `MSFT 보유 $460·RSI77` → ✂️ Z1 지금 33% / Z2 $485~490 / Z3 코어(MA50 $404 이탈청산)
- `BWXT 관찰 $188·RSI26` → 🟢 Z1 지금 probe 30% / Z2 $175~180 / Z3 MA50 $212 회복확인 30%

## 6. 아키텍처 (작은 모듈 다수)

`corvin_jarvis/playbook/`
- `ladder.py` — 순수함수: 기술지표 + side(buy/trim) → 존(가격밴드+비율+상태). 부수효과 없음.
- `position.py` — 현재가 → 활성 존 / 상태 뱃지 / 트리거 bool 매핑 (순수).
- `builder.py` — 종목별 지표 fetch(yfinance·kr_data 재사용) + `portfolio.json` 보고 side 결정 → `Playbook` 객체 리스트.
- `render_text.py` — `[Playbook]` → 푸시 문자열. `channels.send_telegram` 재사용.
- `render_html.py` — `[Playbook]` → 대시보드 HTML 파일.
- `run_playbook.py` — 진입점: build → 렌더 2개 → 푸시 + HTML 저장.

### 데이터 흐름
`monitored_universe.json`(50) + `portfolio.json` → `builder`(지표 fetch) → `[Playbook]`
→ `render_text` → Telegram 푸시 / `render_html` → 대시보드 파일.

### 재사용
- 지표(MA20·MA50·RSI·52wHi·저점) 계산은 기존 `dca_timing.py` / `kr_data.py` 패턴 재사용. 한국 종목은 pykrx(yfinance 금지).
- 송신은 `channels.send_telegram`.

## 7. 에러 처리

- 종목별 fetch 실패 = **그 종목만 skip + 로그 경고**, 전체 run 안 죽음 (기존 graceful 패턴).
- 지표 부족(데이터 < 50봉) 종목 = "데이터 없음" 표시, 추측 금지.
- 송신 실패 = 로그, 다음 실행 재시도.
